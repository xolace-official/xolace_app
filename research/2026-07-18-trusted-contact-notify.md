# CEO Plan: Trusted Contact Notify
Generated by /plan-ceo-review on 2026-07-18
Branch: chore/channels-research | Mode: SELECTIVE EXPANSION
Repo: xolace-official/xolace_app

## Vision

### 10x Check
At 10x, Xolace doesn't just ping one pre-registered contact on a confirm-tap — it becomes
the layer that quietly keeps the people who care about someone in sync with them, without
ever exposing content. The escalation signal already carries `triggerType` and pattern data
across sessions; at 10x that becomes a *trend*-aware contact experience ("checking in has
mattered 3 times this month") rather than a one-shot alert, and the contact-side experience
grows from a bare SMS into a lightweight, no-account "how can I help" companion page. None
of that is this plan's scope — it's the shape the wedge points toward if it works.

### Platonic Ideal
The ideal version: a user never has to decide, in the worst moment, whether to reach out.
The infrastructure already knows who they'd want nearby, and the system's only job is to
make that reach as safe, warm, and non-alarming as humanly possible — for both sides.

## Accepted Scope (added to this plan)
- Approach A only, as approved in the design doc: `trustedContacts` table (phone,
  relationship, `contactAcceptedAt`, `contactOptedOutAt`, `lastNotifiedAt`), inbound +
  outbound Twilio SMS, in-session confirm-mode UI keyed off `escalation_events`
  `triggerConfidence`. Opt-in sequence: (1) user opt-in — adds the contact's phone number
  in-app, which triggers an invitation SMS to that number; (2) contact opt-in — the contact
  replies YES to that SMS, which sets `contactAcceptedAt`; only after both steps is the
  contact eligible to ever receive a check-in message. Cooldown window and confirm-mode
  confidence threshold are unresolved numeric values, explicitly deferred to
  `/plan-eng-review` (not decided here — do not implement against a guessed default).
  Revoke policy: user-side removal hard-deletes the `trustedContacts` row itself (not any
  message history, which lives in Twilio's own logs, not in Xolace's database); any
  in-flight invitation becomes inert because the accept webhook no-ops when it finds no
  matching row. STOP/HELP keyword handling and TCPA-compliant opt-out language are
  carrier-level legal requirements distinct from the app-level `contactOptedOutAt` field —
  both are required, not either/or; `/plan-eng-review` must specify the exact STOP/HELP
  copy. A2P 10DLC registration (typically 2-6+ weeks lead time) must start immediately as a
  critical-path item — it can block launch independent of code readiness and should not be
  treated as a footnote.

## Effort Correction (post-review, outside-voice caught)
Approach A's effort was implicitly under-scoped by assuming partial backend reuse from
Trusted Bridge that does not exist (see corrected "What already exists" table above). No
persistent contact/phone/consent infrastructure exists anywhere in the codebase today.
Actual effort for Approach A should be read as roughly one tier higher than "M" implies —
`/plan-eng-review` should treat this as a fuller ground-up build (schema + two-way SMS +
consent state machine + UI), not a lightweight extension of shipped code. Two other findings
also carried forward from the outside-voice pass, both flagged for `/plan-eng-review`,
neither resolved here:
- `triggerConfidence` was calibrated for a human safety-review queue
  (`escalation_events.reviewedByHuman`), never validated as a real-time UX-gating signal —
  repurposing it at any threshold for an unattended notify trigger is unvalidated.
- Pending (invited-but-not-yet-accepted) contacts have no TTL/revisit trigger — only
  stale-*accepted* contacts were flagged for reconfirmation in the design doc; an
  invitation that's never answered sits in limbo indefinitely with nothing to prompt cleanup.

## Dream state delta
This plan takes Xolace from "proactive support means re-engaging the user" to "proactive
support means the user's own people can be reached too" — the first concrete Phase 2 vision
feature that extends past the app boundary. Gap remaining after this ships: multi-channel
delivery, trend-aware (not one-shot) contact experience, and the separate listener track.

## Required Outputs

### NOT in scope
- WhatsApp, Telegram, or any channel beyond SMS
- Auto-fire mode (no per-event human check) — confirm-mode only, per office-hours sequencing
- Anything from the listener/peer-counselor track
- Weekly summary fan-out to any external channel

### Unresolved numeric/policy values (explicitly deferred to `/plan-eng-review`, not this doc)
- Cooldown duration between repeat notifies to the same contact
- `triggerConfidence` threshold that gates the confirm-mode UI
- Max trusted contacts per user (design doc leaned toward one, matching ChatGPT's model, but
  not locked)
- STOP/HELP exact carrier-compliant copy

### Error & Rescue Registry (carried from design doc, to be expanded in 11-section review)
| Error | Where | Rescue |
|-------|-------|--------|
| Inbound webhook receives reply from unrecognized number | Twilio inbound handler | No-op; do not create implicit contact records from arbitrary inbound SMS |
| Contact never accepts invitation | trustedContacts row with `contactAcceptedAt: undefined` | Never eligible for notify; UI should reflect "pending" state to the user |
| User taps confirm but contact was removed/opted-out since page load | In-session confirm UI | Server-side re-check at send time, not just at render time — stale client state must not bypass the opt-out |
| Two escalation events fire in quick succession before the first SMS send completes | Escalation trigger → notify pipeline | Needs idempotency/locking at the mutation level so a race doesn't double-send before `lastNotifiedAt` is written — flagged for `/plan-eng-review`, not resolved here |
| Contact's phone number gets reassigned/reused by carrier after they opted out or stopped responding | `trustedContacts` row with stale `contactAcceptedAt` | Flagged for `/plan-eng-review`: consider a re-confirmation cadence or expiry on stale accepted contacts, not decided here |
