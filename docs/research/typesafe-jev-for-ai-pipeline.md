# TypeSafe Jev for Xolace's AI Pipeline

**Status:** Research note, no decisions made. Written 2026-09-25.

## What Jev is (and isn't)

Jev is TypeSafe's "System One model" — not a chat/text-generation LLM ([Introduction](https://docs.typesafe.ai/introduction)). It takes a `state` (string/object/array of context) and one or more typed `questions` evaluated in parallel against that same state, and returns typed structured answers directly, no parsing:

- **Choice** — pick one of up to 255 named options → `choice`, full `probabilities` distribution, `confidence` (0–1) ([docs.typesafe.ai/primitives/choice](https://docs.typesafe.ai/primitives/choice)).
- **Score** — rate on a 2–10 level rubric → probability-weighted `score`, `confidence`, `probabilities` per level ([docs.typesafe.ai/primitives/score](https://docs.typesafe.ai/primitives/score)).
- **Noul** — a single yes/no proposition → `noul` probability 0–1, **no confidence field** (two outcomes need none) ([docs.typesafe.ai/primitives/noul](https://docs.typesafe.ai/primitives/noul)).

`confidence` is not a calibration guarantee — it's a statistic computed from how concentrated the model's own probability distribution is ("(3×largest−1)/2" for 3 options), and the docs are explicit that thresholds are domain-specific and must be validated with your own data before trusting them ([docs.typesafe.ai/confidence](https://docs.typesafe.ai/confidence), [patterns/confidence-routing](https://docs.typesafe.ai/patterns/confidence-routing)). Model is `jev-1.13.0`, $0.042/M input tokens, output free, 64k token context ([docs.typesafe.ai/models](https://docs.typesafe.ai/models)) — genuinely ~100x cheaper than a Haiku/Sonnet call per token. Text-only, primarily-English, and explicitly scoped to "gut-check" atomic questions — it is not a substitute for a reasoning chain or for prose generation.

## What NOT to replace

- **`evaluateSafeguard` itself.** The Cognition Layer Constitution and the file's own header are explicit: crisis/escalation decisions are rule-code by design, never model-discretionary (`docs/cognition-layer-architecture.md:31-33`, `safeguard.ts:1-5`). Jev is a probabilistic classifier with a documented English-bias and no calibration guarantee out of the box — swapping deterministic threshold logic for a probabilistic gate in the one place false negatives mean a missed crisis is the wrong trade regardless of latency/cost gains.
- **Claim-strength routing** (`mirrorPlan.ts`/`routing.ts`). Already deliberately deterministic rule-code, and the team already rejected using the classifier's own confidence scalar for exactly the reason Jev's docs flag (a self-reported/derived confidence is not free of domain-specific calibration work).
- **The Cognition Layer Constitution's "no re-derivation" rule** applies here too: Understanding (`emotional_metadata`) is written once per session and read via `internal.understanding.getUnderstanding` — a Jev call re-scoring something Understanding already computed (e.g. re-classifying primaryEmotion downstream in the Reflection Agent) would violate the same rule that currently governs LLM calls.
- **Articulator (mirror text), distiller reflection text, notification/follow-up card copy, kindling `why` lines.** All of these are generative prose tasks by nature (`convex/ai/prompts/articulator.ts`, `distiller.ts`, `convex/ai/prompts/notificationWriter.ts`, `convex/jobs/reflectionDistiller.ts` path). Jev explicitly does not do text generation — it answers typed questions about text, it doesn't write it.

## Prioritized pilot list

1. **Distiller NULL-gate as a Noul pre-check** — lowest risk, clear binary decision already embedded in a prompt, immediate token savings, no safety surface. Best place to validate Jev's plumbing (API auth, latency, Convex action integration) before anything safeguard-adjacent.
2. **Classifier's `intensity`/`specificity`/`requiresFollowUp`/`supportNeed` fields as Score/Score/Noul/Choice, run in shadow alongside the existing Haiku classifier** — highest token-cost leverage (6 judgments per session, run on every reflection), but must be A/B'd against Haiku output before replacing it, since `emotional_metadata` and `safeguard`/`routing` both consume these fields downstream.
3. **`isSurvivorNarrative` second-opinion Noul, additive not substitutive** — the strongest "why Jev" story (guardrails/moderation is TypeSafe's flagship use case) but the highest-stakes surface in this codebase; must be shadow-scored against real (anonymized) past sessions before it's allowed to change a rejection outcome.
4. **`primaryEmotion` as a Choice, keeping the probability distribution rather than just the top pick** — feeds `routing.ts`'s claim-strength gate a richer signal than today's single self-reported float, but only worth building once (1) has proven the integration and (2) there's eval data comparing Jev's distribution shape to the Haiku classifier's actual accuracy on Xolace's own inputs.
5. **`hasMetaNarration` as a Noul** — cheapest possible pilot after (1), but flagged lowest priority since the current heuristic wasn't read in this pass and may not be broken.

## Open questions requiring a product/eng decision

- **Calibration validation before any safeguard-adjacent use.** TypeSafe's own docs concede confidence thresholds are domain-specific and must be tuned on your data (`docs.typesafe.ai/confidence`). Nothing here should touch `evaluateSafeguard`'s inputs until there's an eval harness (Xolace already has `convex/ai/evalMetrics.ts` / `__evals__/` conventions) scoring Jev against a labeled set of past (anonymized) sessions, specifically checking false-negative rate on crisis/trauma content — a single false negative is the highest-stakes failure mode in this app.
- **English-only accuracy gap vs. Xolace's actual user base.** Unclear from this pass whether Xolace serves meaningfully non-English input today (the app is Ghana-facing per `safeguard.ts`'s resource list); if so, Jev's documented CJK/non-English accuracy caveat needs a real answer before broad rollout, not just the classifier's current single-model approach.
- **Who owns the eval harness and the go/no-go bar** for promoting any pilot (1–5 above) from shadow-mode to live traffic — this note stops at "candidate," not "ship."
- **Latency/cost measurement in Convex's actual runtime**, not the docs' claimed ~150ms — Convex actions already run two-three model calls in `Promise.all` (`process.ts:141-158`); whether Jev's real-world latency in this stack beats or is negligible next to the existing Haiku call needs a measured pilot, not an assumption.
