Discovery screen — three structural variants

Discovery is the first tab of the two-tab shell (Discovery / Connect), reached by router.replace('/discovery'). Today it holds two real destinations — Quotes and Reflect — plus a welcome. Each variant below is a different layout grammar, not a different skin: pick the one whose rule for "where does the next module go?" you want to live with for the next year. Every variant is drawn twice — Now (what ships this week) and Later (the same grammar carrying 5–6 modules), so the growth path is visible, not promised.

ConstraintsTwo live destinations. No large header title. Native tab bar owns the bottom 60pt. Text scales with Dynamic Type. Both themes ship.
Non-negotiablesOne primary action per screen (HIG). Every tap target ≥44pt. No emoji as icons. Colors from CSS vars only — no hex.
VoiceCampfire, not dashboard. The screen should feel like a room you walk into, not a console you operate.
Test for eachCover everything but the top 120pt: can you still tell where you are and what the app wants you to do?
Variant A
The Ledge — one hero, then a quiet list
A single dominant surface owns the top third: reflect, phrased as the app's actual question. Everything else collapses into a bordered list under a small "Also here" label. The hierarchy is brutal and legible — one thing shouts, the rest whisper. Growth rule: new modules append as rows. The hero never moves, never competes, never gets a sibling. This is the safest structure and the hardest to make feel special.
PatternVertical priority stack (hero + inset list)
Scales byAppending rows; section labels split them into groups once past ~5
StrengthZero ambiguity about the primary action; rows are the cheapest thing to build
RiskReads as a settings screen if the row list grows past 6 without grouping

Variant B
The Read — content first, action docked
Inverts A. The top of the screen is real content (today's quote, full-bleed and readable), and the primary action lives in a persistent dock floating above the tab bar. The user arrives and reads something instead of being asked to do something — then the dock is always one thumb-reach away regardless of scroll position. Growth rule: content sections and horizontal rails stack below the quote; the dock never scrolls away. This is the structure that gets people opening the app when they don't have anything to process.
PatternContent feed + persistent action dock
Scales byStacking sections/rails below the hero content card
StrengthGives the app a reason to be opened daily even with nothing to say; best thumb ergonomics
RiskDock competes with the tab bar for the bottom edge; needs ~78pt bottom content inset or it clips the last row

Variant C
The Hearth — asymmetric bento
A two-column grid where tiles claim different spans and heights. With two modules it reads as a deliberate composition, not a sparse list — the asymmetry is the design, so emptiness never looks like a bug. Growth rule: every new module is a tile with a declared span (1 or 2) and height class; the grid re-flows itself. This is the most expressive option and the one that most rewards good copy, because each tile is a small poster.
PatternAsymmetric bento mosaic (2-col, mixed spans)
Scales byAdding tiles with a span + height token; order encodes priority
StrengthLooks intentional at 2 tiles and at 8; density without a list feel; great screenshot surface
RiskWeakest primary-action signal of the three — the reflect tile must stay visually loudest or the screen turns into a menu

Which one to build

VariantPick it if…Skip it if…Build cost
A · Ledge Reflect must stay unambiguously the point, and Discovery is a launcher that occasionally gains a destination. You want people opening the app on days they have nothing to say — a launcher gives them no reason to. Lowest. Hero card + a row component you'll reuse in Settings and Timeline.
B · Read Daily-open retention matters and quotes are a real content stream. Also the best thumb ergonomics of the three. The bottom edge is already crowded, or you'd rather not maintain a floating dock against the native tab bar. Medium. Dock needs absolute positioning above the tab bar plus a matching contentContainerStyle bottom inset.
C · Hearth You want Discovery to feel like a place, want density later without lists, and will hold the line on one accent tile. Copy discipline is uncertain — a bento of vague tiles becomes a menu of nouns fast. Medium. One <BentoTile span height /> component and a config array; most future work is data, not layout.
Implementation notes that apply to all three
  • Colors come from CSS variables via className / useThemeColor. The oklch values above are lifted from src/global.css for fidelity only — do not hardcode them in RN.
  • Rounded surfaces use style={{ borderCurve: 'continuous' }}; the mockups approximate this with plain border-radius.
  • Icons are SymbolView from expo-symbols (SF on iOS, Material on Android). The inline SVGs here are stand-ins: arrow.right, quote.opening, chevron.right, flame.fill, heart, square.and.arrow.up, chart.bar.
  • Root is a ScrollView with contentInsetAdjustmentBehavior="automatic"; padding goes on contentContainerClassName, never the ScrollView.
  • Reflect navigation stays router.replace('/') so no back stack accumulates between the tab surface and the idle screen. Quotes is a normal push.
  • Entrance: stagger 30–50ms per element with EaseView, respect motionPreference. Press feedback via PressableFeedback + playSoftPress().
  • Every tile/row is one tap target ≥44pt with an accessibilityLabel; the greeting is decorative and should be excluded from the a11y order after the first read.
  • Copy is time-of-day aware in all three. That's a pure function of the clock — no query, no cost.
