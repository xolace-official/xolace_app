Assumptions & how to tighten this

This model is built from reading the pipeline code (prompt composition, `max_tokens` caps, cache TTLs, gating rules), not from measured token counts — no request in this codebase carries `usage` telemetry that was available to sample. Treat every number above as an order-of-magnitude estimate.

  • 20 sessions/user/month — a stated cadence, not a measured one. Swap in PostHog's actual `sessions completed` rate per user to rescale everything linearly.
  • Consolidation cadence — modeled as 1 event per 5 completed sessions (the codebase's stated gate). Real cadence depends on how often the 7-day fallback fires for low-frequency users, which pulls cost up per-session for them.
  • Clarify rate (0.4 turns/session), slot-fill (30%), follow-up (15%) — plausible mid-range guesses for a reflection-style UX, not measured funnel rates.
  • Prompt sizes — read off the code's prompt-builder structure (semantic profile + episodic recall + recent mirrors for the articulator; classification rules + pattern summary for the classifier) and estimated in tokens, not counted with the `count_tokens` endpoint against real user input.
  • No prompt caching on Sonnet calls — the codebase doesn't set `cache_control` anywhere; the articulator's system prompt is rebuilt per-user per-session, so there's no cache credit to apply here even though the pipeline is a good caching candidate.
  • To replace estimates with real numbers: pull 30 days of Anthropic `usage.input_tokens` / `usage.output_tokens` from the Convex Anthropic client's response logging (if `console.log`s of API responses exist — the codebase keeps these intentionally for beta debugging) or from the Anthropic Console's usage dashboard, filtered by API key if one key is Xolace-only.
Built from a full read of convex/ai/, convex/jobs/, and convex/crons.ts. Pricing per Anthropic's published rates (Sonnet 4.6 $3/$15, Haiku 4.5 $1/$5 per million tokens, input/output). Not a substitute for measured usage.
